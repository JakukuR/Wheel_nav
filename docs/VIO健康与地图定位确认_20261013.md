# VIO 健康与地图定位确认修复（2026-10-13）

## 问题和职责

`vo_watchdog` 名称及 `/r680_nav/vo_watchdog_healthy` 保留兼容现有消费者；名称不再作为判断前端类型的依据。这个话题仍是定位导航的最终门控，不是原始 VIO 健康。`odom_source` 决定真实质量来源：

| 前端 | 原始质量证据 | 最终权限 |
|---|---|---|
| RGB-D | `/d455_slam/odom_info` 与 `/r680_nav/vo_odom` | watchdog 的地图确认 |
| cuVSLAM | `/r680_nav/vio_tracking_healthy`，由 cuVSLAM 的惯性初始化、跟踪及有效性检查产生 | watchdog + 连续里程计权限；有界补偿显式区分 |
| OpenVINS | `/openvins/estimator_status` → 新 `/openvins/tracking_healthy` | 原有 `/openvins/motion_ready`，继续叠加地图、着地、输出时效及 commissioning 限制 |

OpenVINS 继续使用自己的质量门控，不接入会终止 RGB-D/cuVSLAM 进程的旧 watchdog。只有 `VIO_TRACKING`、有效且新鲜的状态、合格不确定度、最近视觉更新及恢复帧数成立，才发布 tracking healthy。`INERTIAL_ONLY` 不算 VIO 健康；状态报告持续到达也不能掩盖 `state_stamp` 陈旧。地图/着地/运动授权不会被混同为原始估计器质量。

`interface_monitor` 增加独立的 motion permission 输入，必须同时通过对应原始质量和最终权限。cuVSLAM 定位模式只在显式有界降级且连续里程计有效时允许原始 VIO 不健康；mapping 和 OpenVINS 不打开这个例外。

cuVSLAM watchdog 同时接收原始健康与连续里程计健康。原始健康用于建立地图确认和更新可信锚点；连续里程计只负责保留已有定位下的有限运动连续性。保留原有轮速/IMU 距离、转角、时间、不确定度预算，不扩大预算。原始健康丢失到连续节点发布降级标志之间允许最多 0.20 秒交接，且连续健康必须新鲜为真，避免立即撤销它需要的 watchdog 输入。交接期之后必须有明确降级状态；状态会发布 `bounded_continuity_vio_unhealthy`。

## 替换永久地图匹配锁存

删除 `initial_map_matched_` / `initial_localization_seen_`，改用 `MapLocalizationEvidence`。

1. `Info` 中已接受的 loop/proximity/landmark ID 只产生候选。回环本身不能证明当前已重定位。
2. 定位 pose 必须属于 map、数值和协方差合格，使用源时间戳检查时效、单调性及当前恢复代际。
3. 候选匹配与有效定位 pose 的源时间差不超过 50 ms；当前前端必须正常跟踪、里程计和 TF 必须有效。
4. TF 比对采用当前 map→odom 修正量与观测时刻 odom→base，固定帧参数 `localization_odom_frame` 默认 `d455_floor_odom`。避免用当前移动后的底盘位置比较过去观测，也兼容地图 TF 的时间容差。误差仍使用原有 0.40 m / 0.80 rad 门限。异步 TF 尚未到达时不刷新证据。
5. 一次验证后允许后续合格定位 pose 维持确认，不要求每帧产生新回环。位姿按源时间而非接收时间过期；标准时效仍为 3 秒，有界补偿沿用原配置的有限地图宽限。
6. 已确认定位的 pose/TF 失配、时效失效、里程计失效、手动初始位姿、前端故障/重启或 ROS 时钟回退都会撤销确认。晚到的前一代证据不能重开门控；必须有本代新的配对证据。

这项修改只影响定位导航门控和对应前端质量接线，未新增无图游荡、SLAM 生命周期切换或自主探索。OpenVINS 实车输出的标定/验收限制仍保留。

RTAB-Map TF 时间容差与地图修正量语义参考上游 [CoreWrapper.cpp](https://github.com/introlab/rtabmap_ros/blob/ros2/rtabmap_slam/src/CoreWrapper.cpp)。部署参数仍以本机 Jazzy / rtabmap_msgs 0.22.1 和当前配置为准。
