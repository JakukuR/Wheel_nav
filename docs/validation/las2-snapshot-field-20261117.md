# LAS2 20 Hz + 10 Hz 预览 + 单帧三维距离场（2026-11-17）

## 本版行为与范围

在 Orin NX 16 GB 的现有 LAS2-S FP16 链路上，保留原生宽高比缩放后的 384×216 有效图像，上下各填充 36 行送入 384×288 网络。深度仍为 384×216 / 16UC1 毫米，20 Hz；不将深度放大回 640×384。

新增 `--preview-rate`，本次运行设为 10。左目校正预览与深度伪彩预览分别按同一帧起始时钟限频，避免推理前判断、推理后重置时间造成额外漏帧。独立 JPEG 节点质量 70，编码上限 15 Hz；实际输入上限 10 Hz。编码端留余量是为了避免两个相同的 10 Hz 限频器因时间戳抖动再次丢帧，不是将网页改为 15 Hz。

`stereo_snapshot_field` 在有人订阅 `/r680/debug/stereo/field` 时才订阅原生深度和 CameraInfo。5 Hz 定时器只取最新一帧，复用 60×40×60 的工作数组；不排队追赶，不先展开完整 XYZ 点云。无人订阅时退订输入。每帧清空上一帧状态，计算结束后输出最多 4,000 个表面体素索引和三个平面切片，由浏览器绘制。

这是一版**单帧、相机坐标系下的三维体素距离场调试视图**，没有实现位姿配对、TSDF 时序融合或世界坐标地图。未连接导航/电机输出，未启动人物跟随。已有 RGB 深度投影接口保留，只有消费者订阅时才执行；地面与人物尚未剔除。

## 几何与未知区域

- 光学坐标系：`sunplus_left_rect_optical_frame`，x 向右、y 向下、z 向前。未对齐重力。
- 空间范围：x ∈ [-1.5,1.5)，y ∈ [-1,1)，z ∈ [0,3) 米；体素边长 5 cm。
- 所有有效深度端点先标为表面体素，防止后续自由空间标记覆盖命中。
- 其余体素中心投影到深度图，仅测量有效且位于表面前方时标为已观测自由区域；采用半体素对角线作为前方余量。这是中心采样的近似可见性，不保证整个体素可安全通行。
- 无效深度、视野外、遮挡后方保持未知，不当作自由空间。
- 对表面种子和已观测自由种子分别执行三轴精确平方欧氏距离变换。外部为到表面体素中心的正距离，表面体素内部为到自由体素中心的负距离，截断 ±1 m；未知为 NaN，JSON 中为 null。
- 距离是离散体素中心距离，并非真实连续表面净空；没有机器人足迹膨胀，不能直接当作导航碰撞距离。
- 切片 y = -0.225、-0.025、0.175 m；黑色为未知，红色为表面。
- 不做跨帧累积，因此移动障碍不会在下一帧留下历史表面；代价是不能借历史观测补全当前遮挡区域。

## 输入与失效处理

仅接受已校正的 `16UC1` 小端深度，宽高、frame、CameraInfo 内参和零畸变模型一致。深度与内参时间差不得超过 100 ms；深度源龄不得超过 300 ms，未来时间容差 20 ms。计算后再次检查源龄。同一深度时间戳不重新作为新观测发布。

输入停更、布局错误、frame/内参不符时发布 `available=false`；前端清空旧画面。前端也检查消息来源帧、数组边界、距离符号、未知 null 编码和时间，断流超过 750 ms 时清除旧图。未观测区域不会显示成安全空间。

## 实机结果

硬件沿用现有 Orin NX 16 GB Super / JetPack 7.2 / TensorRT 10.16.2 / CUDA 13.2 / ROS 2 Jazzy。使用已验证的 `models/stereo_candidates/las2_s_384x288_fp16.engine`。以下 CPU 以单个逻辑核 100% 为单位，不是整机占用。

| 指标 | 仅原生深度，65 s | 同时订阅 RGB 对齐深度，45 s |
|---|---:|---:|
| 原生深度 | 19.975 Hz | 19.975 Hz |
| RGB 对齐深度 | 未请求 | 19.976 Hz |
| 左目 / 深度网页 JPEG | 9.988 / 9.987 Hz | 9.987 / 9.988 Hz |
| 深度进程 CPU | 24.80% | 34.86% |
| 单帧距离场进程 CPU | 6.86% | 6.82% |
| 两个 JPEG 进程 CPU 合计 | 2.89% | 2.89% |
| 上述四个进程合计 | 34.55% | 44.57% |
| 原生深度消息源龄 p95 | 50.08 ms | 49.97 ms |
| RGB 对齐消息源龄 p95 | — | 56.14 ms |

CPU 合计不含 RGB 采集/校正、foxglove_bridge、HTTP/WS 转发、检测、VIO 或导航。对齐输出为 640×360 稀疏深度；测试样本有效覆盖约 17.3%，没有用插值填满空洞，不能当作稠密 RGB 深度。

距离场另测 60 s：5.000 Hz，收到 292 帧均有效（初次 DDS 发现消耗部分测量窗口）。计算 p50/p95/max = 11.16/12.37/13.11 ms，含表面/切片 JSON 对象构造，不含最终序列化和发送；进程 CPU 已包含这些开销。消息源龄 p50/p95/max = 81.43/106.73/116.24 ms；JSON 约 88.3 KB/帧，约 0.44 MB/s，浏览器多开会增加转发流量。样本场景约 1,000–1,200 个表面体素，不能据此保证所有场景的计算/网络上限。

65 s 测量中原生深度曾出现一次约 336 ms 的接收间隔峰值和约 324 ms 源龄峰值；不能宣称硬实时无抖动。后续 45 s 对齐测试原生深度最大间隔 52.65 ms。测量结束 CPU/GPU 温度约 96.2/94.2°C；这不是长时间热稳态验收，未改变系统温控。

## 运行与回退

进程和完整命令记录在 `.runtime/las2_field_preview/processes.json`，部署前进程记录在同目录 `before_processes.json`；测试结果为 `live_measure.json`、`aligned_measure.json`、`field_measure.json` 和 `ros_contract.log`。运行数据、模型、截图不入 Git。

```bash
# 单帧调试距离场；ROS 环境由包装器设置，flock 防止重复启动
bash ./robot_depth_field.sh
# 深度生产者（仅在原生产者已退出、相机锁空闲时使用）
bash ./robot_stereo_depth.sh --model las2_s --profile 384x288 --max-rate 20 \
  --preview-rate 10 --direct-camera /dev/v4l/by-id/usb-SunplusIT_Inc_USB_Global_Camera-video-index0
```

左预览编码器订阅 `/camera/stereo/left_rect/image_raw`，输出 `/r680/debug/calibration/left/compressed`；深度编码器订阅 `/camera/stereo/depth/preview`，输出 `/r680/debug/stereo/depth/compressed`，两者 `max_rate:=15.0 quality:=70`。现有 `las2_inputs.launch.py` 新增 `preview_rate:=10`；原有默认深度频率和分辨率不改，重启时需显式指定 `profile:=384x288 depth_rate:=20`。

主页面 `http://192.168.50.1:18081/` 增加距离场面板；独立页 `/field-lite.html`。关闭距离场页面/订阅即可停止距离场计算；终止已记录的 `stereo_snapshot_field` 进程不影响深度生产。要退回低频预览，以 `--preview-rate 2` 重启深度生产者，并恢复编码器原上限。新增地图仅在调试命名空间，不需要改导航话题来回退。

后续若进入可导航的融合地图，需要先打通图像时刻完整位姿与相机到机身 TF、按 RGB 掩膜与时间配对剔除人物，再引入局部 TSDF/ESDF 融合与导航接口验证。本版没有用单帧显示替代这些步骤。
