## 坐标基准与刚体关系

URDF 的根 link 名为 `base_link`，CSV 的 `base_link` 行在 `Coordinate System` 列明确写的是 `base_point`。所以 `base_point` 是这个 CAD 根坐标系的名称，URDF 导出时使用了 `base_link` 这个 link 名。用户根据“四个 ToF 中间、矮一点”的位置特征确认其为 IMU：根原点位于四个 ToF 的平面包围范围内，比前两个 ToF 低 35.893 mm，比后两个低约 26.245 mm；它不严格等于四个安装点的几何中心。IMU 芯片原始测量轴是否与 CAD 轴同向，仍需电控或静止/转轴实测确认。根 link 的 `<inertial><origin>` 是质心位置，不能当作 IMU 平移。

全部相机安装点及四个 ToF 都通过 fixed joint 直接连接 `base_link`，不经过轮腿活动关节。因此按本版 CAD，它们与 IMU 属于同一机身刚体，改变轮腿关节角不会改变这些安装外参；实物有活动支架或安装变更时需重新核查。

## 与现有相机及 IMU 数据的对接边界

1. 用户已确认物理对应：DICOTA 4K RGB 为 `upper_camera_R`，Sunplus 同步黑白双目为 `bottom_camera_L/R`。现有 UVC 图像 frame 是 `dicota_color_optical_frame`、`sunplus_left_optical_frame`、`sunplus_right_optical_frame`。拼接画面左右半幅仍需按实物遮挡检查，设备身份确认不能代替图像半幅顺序验证。
2. CAD 相机安装 frame 不等于已标定的光学 frame。光学轴使用 x 右/y 下/z 前；只有确认 CAD 安装轴是 x 前/y 左/z 上时，才可用 rpy `(-pi/2, 0, -pi/2)` 作为安装坐标至光学坐标的轴约定转换，还要确认安装原点是否为光心。当前不自动添加该 TF。
3. 37 mm 是 CAD 安装点间距，不能直接写入深度算法作为已标定光学基线。三路内参、畸变、双目精确光学外参以及 RGB 对齐外参仍需 AprilGrid/Kalibr 求解；CAD 用于初值与量级/左右方向复核。
4. 电控此前代码把 `/imu/data` 标为 `base_Link`，而本 URDF 根为 `base_link`，大小写不同，是不同 frame。先确认数据实际轴向及姿态约定，再统一 frame 或建立真实的变换；不能靠修改字符串或随意加 identity TF 证明对齐。若原始数据是 IMU 芯片坐标，宜使用明确的 IMU frame 并提供轴向旋转。
5. ToF 目前只得到四处安装几何。还缺各通道与物理位置的对应、ROS 话题/消息格式、单位、有效距离/失效值、时间戳、视场及实际测距轴。ROS `Range` 的测距轴约定为其 frame 的 +x；若模块以其他轴输出，需先转换到真实 Range frame。不能把四个测距值直接当作机身离地高度；应结合姿态、安装偏移与视线方向，估计地面交点/局部平面。

## 校验结果与限制

原始模型有 17 个 link、16 个 joint，单根 `base_link`，无重复 parent、断链或环。八个传感器安装 joint 全为 fixed，URDF 与 CSV 的六个外参逐项一致，四元数归一。当前导出为 8 个 link、7 个 fixed joint；未修改原始 CAD。

完整 CAD 的轮腿关节还存在 `limit.lower > limit.upper` 的情况：`joint_hip_R`, `Joint_thigh_R`, `Joint_calf_R`, `Joint_wheel_R`, `Joint_hip_L`, `Joint_thigh_L`, `Joint_calf_L`, `Joint_wheel_L`。当前只使用传感器固定子树，完整轮腿模型需要单独核对限位、轴向、命名和 ROS 2 包结构，不能直接用原始 CAD 启动控制。

校验覆盖 XML/树结构、CAD/CSV 一致性和数学转换，不代表光学标定、IMU 轴向、ToF 测距方向或运行 TF 已验收。
