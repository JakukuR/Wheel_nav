## 电控如何知道启动姿态

已只读核对当前电控 `ros2_ws/src/motor35_control_cpp/src/imu_serial.hpp`、`wit.hpp`、`perception.cpp` 和 `core.cpp`：

1. WIT IMU 输出自身四元数。WIT 解析器将其归一化，并按已有 `imu_to_base_xyzw` 转换安装方向。
2. 当前启用 `state_estimation.mode=zju2026` 时，`SerialImuParser` 用第一份有效 WIT 四元数调用 `MahonyAttitude::seed()`，保留启动姿态和朝向；随后以陀螺仪和新鲜加速度更新主机 Mahony，生成发布给 ROS 的样本。六轴融合没有绝对航向约束，yaw 会漂移。
3. `/imu/data` 已包含这一路融合后的四元数、角速度和加速度。适配器直接读取，不再实现 AHRS、重力解算、零偏估计或位置积分。
4. 控制 `Core::reset()` 把内部前向位置/速度清零，并用当时实测 yaw 初始化 `yaw_ref`。目标站高与目标站姿来自调参配置/控制表；它们不是传感器测得的全局 xyz 或离地高度。
5. 控制内部已经通过轮腿运动学、角速度补偿和速度 KF 算前向速度，但目前只在控制 step 中更新，不能把 standby 下的默认零值当实时速度。此适配器不复制其实现，也不为取得该量启用控制。

本次没有修改 `/home/onana/wheel_leg_nav20261105_lqr10_cpp` 的模型、零位、配置或代码。

## 输出接口

| 话题 | 类型 | 含义 |
|---|---|---|
| `/imu/data` | `sensor_msgs/msg/Imu` | 原电控发布的融合 IMU，保持原样，供后续 VIO/SLAM 使用 |
| `/joint_states` | `sensor_msgs/msg/JointState` | 电控实测 `q_rad` 的 8 个关节位置，弧度；不取目标 `reference_q_rad` |
| `/robot_state/attitude` | `geometry_msgs/msg/QuaternionStamped` | 已有 IMU 姿态的启动航向参考表示；启动 yaw=0，保留 roll/pitch；不含位置 |
| `/robot_state/rpy` | `geometry_msgs/msg/Vector3Stamped` | 上述四元数的 roll/pitch/yaw，分别为 vector.x/y/z，单位 rad；这是欧拉角诊断量，不能当普通空间向量旋转 |
| `/robot_state/status` | `std_msgs/msg/String` JSON | 两路输入是否新鲜、计数、错误原因、时间依据与姿态来源 |

`/joint_states` 的关节顺序、名称直接对应电控现用模型：

```text
abad_L_Joint, abad_R_Joint, hip_L_Joint, hip_R_Joint,
knee_L_Joint, knee_R_Joint, wheel_L_Joint, wheel_R_Joint
```

原 JSON 状态没有 qd、effort 或逐关节 ROS 采样时间，因此 velocity/effort 留空，header.stamp 明确使用适配器接收状态的 ROS 时间。正常输出频率受原状态话题约 20 Hz 限制，不宣称硬件采样同步。

姿态适配保留 `/imu/data` 的原 header.stamp，只做 `q_start=q_z(-yaw_initial)*q_source` 的坐标参考变换；没有再估计一次姿态。输出参考名为 `imu_start_gravity`，被描述的机身/IMU frame 仍为源消息的 `base_Link`。该参考只用于读取姿态，适配器不广播 TF。

缺消息、超时、控制 ready=false、gate 非空、关节数组错误或四元数无效时，停止相应数据输出并在 status 中标记不可用；姿态和关节状态互不阻塞。不伪造 xyz、地面高度、Odometry 或零值数据。

## 供局部跟随和 SLAM 使用

- 局部跟随可以读取现有 IMU 或 `/robot_state/attitude`，以及标准 `/joint_states`；关节名与现用电控模型配套。
- SLAM 的 IMU 输入继续使用原 `/imu/data`，需要原角速度和加速度，不能用只有四元数的诊断话题代替。相机内外参、轴向和采样时间关系仍按三相机标定方案核对。
- `JointState` 是关节状态，不是机身全局位姿。后续可由统一 robot_state_publisher 配合现用模型建立关节 TF；`map→odom→base` 的定位变换由后续 SLAM/里程计拥有。本适配器不争用这些 TF。
- CAD 的 `base_link/base_point` 与电控的 `base_Link` 仍要按安装几何对接，不因话题转换而变成同一坐标原点；不改电控模型，也不擅自补 identity TF。

## 启动和查看

本轮已启动一份只读适配器，无需重复启动。它未设置开机自启；以下命令用于之后手动启动。

```bash
cd /home/onana/ros2_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 run wla_robot_state robot_state_adapter --ros-args \
  --params-file /home/onana/ros2_ws/config/robot_state/new_orin.yaml
```

另一个同环境终端：

```bash
ros2 topic echo /robot_state/status
ros2 topic echo /joint_states
ros2 topic echo /robot_state/rpy
```

参数在 `config/robot_state/new_orin.yaml`：源 IMU `/imu/data`、源状态 `/motor35_powered/state`、源 frame `base_Link`、目标关节话题 `/joint_states`、输入最大年龄 0.10 s。只启动此适配器不会启用电机。网页现已接入 Kalo，见后面的“网页实时显示”。
