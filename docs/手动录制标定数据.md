# 手动录制三相机标定数据

当前相机已经切到约 4 Hz 发布，分辨率和方向保持为左右 1280×720 正立横屏、RGB 1920×1080。网页会显示约 4 fps。UVC 捕获模式仍为双目拼接 2560×720/60、RGB 1920×1080/30；降低的是 ROS 发布和录包频率，不改焦点或缩放。

## 直接开始

在本机终端输入：

```bash
ssh onana@192.168.50.1
cd /home/onana/ros2_ws
./robot_calibration_record.sh
```

等终端显示 **“三路已订阅，现在开始摆板”** 后移动标定板。按 **Ctrl+C** 提前结束；不按也会在启动后的 180 秒墙钟上限正常停止。结束时等到 **“录制已结束并保存”** 再关闭终端。

另录 120 秒时：

```bash
./robot_calibration_record.sh --duration 120
```

只检查是否能录制，不启动录制：

```bash
./robot_calibration_record.sh --dry-run
```

正式数据保存在 `/home/onana/calibration_data/manual_年月日_时分秒_JST/`。目录内有原始 MCAP `bag/`、标定板 `target.yaml`、实际配置 `session.json`、日志 `record.log`、结束状态与每路计数 `recording_result.json`。

## 入口做了什么

- 使用现有原始图像、CameraInfo 和状态话题，原分辨率和 header 时间戳保留，不录网页 JPEG。
- 检查两台相机属于本工作区、发布频率不超过 5 Hz、RGB 自动对焦已锁定，拒绝重复录制。
- 按实际发布频率预估所需空间，另预留 5 GiB；录制中低于预留量会请求正常停止。当前 4 Hz 三路原始图像约 47 MB/s，3 分钟约 8.5 GB，另有少量封装开销。
- Python 入口只负责进程、墙钟计时和状态记录；图像实际由原生 rosbag2 MCAP recorder 写入。
- Ctrl+C、墙钟到时、空间不足和监控异常都向 recorder 发 SIGINT，并等待缓存与 metadata 落盘；不使用 SIGKILL 结束写盘。
- 打印录制器报告的缓存/传输消息丢失数。有 metadata 不表示标定数据已验收；日志中的消息丢失数可能包括 CameraInfo/status，不能直接当图像丢帧数。

不要把 `ros2 bag record --max-bag-duration` 当作总录制时长限制；它是分包时长。新入口使用独立的 `time.monotonic()` 墙钟上限。

## 如果相机尚未启动

只在没有其他采集进程占用相机时，在一个常驻终端运行：

```bash
cd /home/onana/ros2_ws
./robot_camera.sh run both --publish-fps 4
```

另一个终端再运行手动录制入口。若已经有 30 Hz 的采集进程，需要先正常结束原采集再换成 4 Hz，不能重复启动。相机总启动器退出会回收两路采集进程；入口已改为直接启动实际采集程序，避免额外 ros2 run 包装进程留下相机占用。

若 RGB 自动对焦开着，先将标定距离附近的板对清楚，再关闭连续对焦并确认画面清晰。不要在同一轮录制中来回改变对焦。当前已锁定；入口不会自动改镜头设置。

## 怎么摆板

固定机器人，每个姿态停稳约 2 秒。6×6 AprilGrid 不要求整板在全部相机里完整可见，但本机 Kalibr 默认每帧至少检测到 7 个标签；尽量保留更多完整标签、白边和不同方向的角点。优先补左右目同时可见的区域，再补 RGB 与一路黑白的共同标签，覆盖中央、四角、近远距离和不同倾角。

约 4 Hz 发布时独立 RGB 相机的采样相位可能超过 25 ms。离线只选停稳段，再按实际相位设近似配对窗口（例如已有静态方案的 0.15 秒）；不能直接套用上一包 30 Hz 数据的 25 ms 共视检查窗口。动态相机—IMU 标定不适用这套静态采集方式。

## 本轮验证与边界

- wla_uvc_camera 构建及 35 项现有测试通过。
- 30 Hz 模式会被录制入口拒绝；4 Hz 模式 dry-run 通过。
- 墙钟 8 秒测试正常收尾，实际墙钟 8.27 秒；Ctrl+C 模拟测试正常收尾，三路图像均有数据。
- 最终版本 5 秒墙钟测试正常收尾，实际墙钟 5.28 秒，三路有图像且 metadata 存在，日志没有报告缓存或传输丢失。另一轮短测曾报告 7 条传输层消息丢失，入口已加入结果记录和提示，不宣称零丢帧。
- 总相机启动器的 SIGINT 测试后，两台相机采集子进程均退出；随后重新启动了 4 Hz 模式。
- 验证包仅在 `.runtime/calibration_recorder_validation/`，不是用户的新正式标定录制。当前没有替用户开启下一轮正式录制。

## 左目暗圈检查

在两路同一原始时间戳的白墙图上，左目中心灰度约 197、右侧边缘约 97；右目对应取样约 209/169。原始图已经表现为左路更强的渐变暗角，不是网页遮罩或旋转程序生成。取样区避开了左侧人物，但墙缝、照明和自动曝光仍影响测量；灰度比不是线性光照比，不能作为严格平场标定。

当前无法仅凭这些图判断是镜头像场/自然暗角、镜筒/支架挡光，还是两路相机内部处理差异。可先检查镜头前外圈、通光孔和保护件有没有遮挡；保持焦点与几何安装稳定，继续用均匀照明检查。若要做亮度补偿，应单独采集合适的平场数据。本轮没有调高增益、裁切、修改内参或写入暗角补偿。
