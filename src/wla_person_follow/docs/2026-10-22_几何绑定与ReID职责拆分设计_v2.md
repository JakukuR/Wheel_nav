## 1. 范围、原则与验收边界

**代码确认**：当前 `SimulationFollow.tick()` 在 `reid_enabled` 时把 `TargetIdentity.state in ('enrolling','expired')` 作为输出阻断条件；`TargetIdentity.select()` 又要求 `seed_count>=2` 且 `state=='tracking'`。因此当前实现确实让外观登记/找回审核拥有“关闭目标几何绑定和运动”的能力。

**代码确认**：当前 `SimulationEngine.step()` 在目标测量存在时直接执行 `self.people.tracks.pop(observation[3], None)`，把当前目标从路人轨迹集合移除。目标身份进入异常状态后，这一步与 `resolved_id` 是否为空共同决定目标点是否仍作为普通路人参与预测。

**推测**：用户现场站在车前约 1 m、网页中确认 ID 后才发任务，是解释初始误阻挡的重要现场条件；但原日志没有记录目标点是否实际写入占据格，因此不能把该次 `front_blocked` 唯一归因于目标点云。

核心原则如下：

1. 用户选中的 BoT-SORT 几何轨迹建立“几何绑定”；同 ID、位置连续和合法测量足以让绑定立即生效。
2. ReID 只负责后台登记、监督、异常保护和轨迹断开后的找回；不能因一次外观低分关闭目标掩码或切断正在连续的几何轨迹。
3. 只有轨迹断开、位置突跳或确认切换到另一条轨迹时才触发找回。
4. 第一批先解决“几何连续时不被 ReID 卡停”和“前方检查不要把目标中心当障碍”；全人物特征缓冲、匿名占据来源重分类和统一 Kalman 继续延后。

### 1.1 两批范围

第一批在本轮按六个本地提交实施：

| 提交 | 范围 |
|---|---|
| 1 | 几何绑定与独立 `select`；同一提交加入前方检查目标端截断 |
| 2 | 后台登记、监督窗口、邻近歧义/可疑、视角模板扩充、可疑出口和缺测宽限 |
| 3 | 丢失时间轴：0–8 s 主动搜索，8–30 s 被动找回，30 s 结束并释放任务；不加入全人物缓冲或新消息协议 |
| 4 | 目标掩码只跟随几何绑定 |
| 5 | 前方检查策略接线和倒车独立开关；不含目标归属匿名格豁免 |
| 6 | 诊断日志字段与最小 Web 状态区分 |

以下内容在 v2 中保留设计，但默认不实施：

- 全人物约 2 s 外观特征缓冲和候选批次新消息协议。
- 占据格来源、历史重分类及按来源删除。
- 所有人物严格分离出静态占据通道、只进入人物通道。
- 目标归属占据格豁免。
- 空间 Kalman 与 `TargetIdentity` 平滑预测的统一。

**推测**：延后理由是上述功能都依赖可靠的逐点或逐格来源、全人物生命周期或独立消息协议；当前没有这些字段，仓促加入会把“目标历史点”和旁边墙/路人混在一起。重新启动条件是用本批新日志证明至少出现以下一种情况，并形成可回放的真实 RGB-D 包：目标历史点持续制造阻挡；两次目标与路人轨迹交叉后无法按现有 BoT-SORT ID 和外观找回；缺测停走显著影响跟随；或目标背面跟随无法通过当前视角扩充稳定恢复。延后项至少需要连续两段不同场景的复现证据，不能只凭单次主观观察启动。

## 2. 开工前代码事实

### 2.1 地图、目标与身份

- **代码确认**：无任务时深度地图仍更新。`SimulationFollow.compute()` 在有效深度、内参、TF 和轮速存在时处理深度；`active` 只控制目标观测、身份和掩码分支。
- **代码确认**：活动任务切换时，同一轮速参考会复用已有占据地图；当前没有按目标 ID 清除目标历史点的机制。
- **代码确认**：目标特征登记要求两个不同且满足当前位置门限的合格帧，第二帧距第一帧不超过 0.6 s。**推测**：检测约 15 Hz 时，条件理想后通常约 2–4 个检测/控制周期完成，具体受推理队列和求解延时影响，未测得硬上界。
- **代码确认**：`TargetIdentity.consume()` 每收到一个特征批次就增加 `feature_frames`；低质量特征不会形成可评估向量，但原状态机可在没有有效匹配时进入 `searching`，并把待确认候选清零。
- **代码确认**：当前 `TargetIdentity.select()` 在登记未完成、状态不是 `tracking` 或几何超过 0.30 s 时返回空；当前位置突跳通过预测位置和增长半径硬拒绝，没有宽限。

### 2.2 前方检查与倒车

- **代码确认**：`BlockedRecovery._path_samples()` 从当前车位置连到目标估计，最多采 1.4 m，再交给 0.316 m 相关门限及 MPC 扫掠检查。
- **代码确认**：旧策略只有在持续 `blocked` 且实测速度很小的 2 s 后才尝试倒车；`rear_clear` 检查占据图、未知区和预测路人轨迹。轮式底盘的现有后方缺少独立传感器证据时，`rear_clear` 通过不等于物理后方安全。
- **代码确认**：目标中心偏移参数 `surface_to_center_offset_m` 当前为 0.28 m；这个偏移是显式可配置的人体表面到中心近似，不是动态测量。

### 2.3 检测字段和消息

- **代码确认**：`RelativeFollower.receive()` 对每条人物记录要求严格键集合 `{detected,label,id,yaw,distance}`。直接增加 `bbox`、`confidence`、`depth_samples` 或原生生命周期键会使整个 `relative_objects` 帧被拒收。
- **代码确认**：当前 `relative_objects` 可提供字符串 ID、布尔检测、标签、车体方位和表面距离；批次还带源时间戳、session/epoch 和启停门控。
- **代码确认**：当前特征请求在健康跟踪时主要请求目标 ID；即将丢失及空间候选阶段可请求附近候选，但 `relative_objects` 本身仍受四人特征 CPU 上限约束。
- **代码确认**：原生轨迹寿命、框、深度样本数、置信度没有进入第一批可消费的相对消息。框质量检查存在，但只在检测器内部生成外观特征时使用。
- **代码确认**：现有 `relative_objects` 字段足以实现“同 ID + 位置连续 + 新鲜度”的几何绑定，不足以实现框交叠或逐点质量审核。因此第一批可实施，框与原生生命周期进入第二批独立字段路径，不能原地扩展严格键集合。

### 2.4 配置、日志和 Web

- **代码确认**：当前 `sim_follow.yaml` 启用 `target_mask_enabled` 和 `reid_enabled`，没有预设校验，也没有统一拒绝任意组合。
- **代码确认**：当前状态已包含 `reid`、`target_mask`、`resolved_target_id`、`target_observation`、诊断序列和规划候选；已有前方阻挡的格/路人来源结构，但旧快照并不总能直接展示所有新语义。
- **代码确认**：当前 Web 俯视图把 ReID 状态拼到跟随状态文字中，尚未区分“几何绑定”和“ReID 监督/找回”。
- **代码确认**：现有真实记录不满足精确复现：OpenVINS 运行目录的 mcap 是 D455 红外/IMU，`follow-stall2-packet.npz` 只有一个点包，本地 depth 示例是合成数据；没有所需的真实彩色图、对齐深度、检测、跟随状态和底盘控制联合录制。

## 3. 状态机与职责边界

### 3.1 几何绑定

**推测**：采用以下状态，状态值将写入状态日志：

| 状态 | 进入条件 | `select()` 返回值 | 运动含义 |
|---|---|---|---|
| `bound_untracked` | 用户选择且当前 ID/几何合法；登记未完成 | 当前绑定 ID | 状态层不因外观阻断；真实几何丢失才停 |
| `bound_tracking` | 同 ID 和位置连续性持续，外观登记可完成或未完成 | 当前绑定 ID | 正常跟随；可疑时另加停车/限速策略 |
| `bound_coasting` | 当前目标行缺失，但未超过 0.30 s 新鲜度之后的附加宽限 | 当前绑定 ID | 由 Kalman 短时预测；单帧缺测不停平移 |
| `suspect` | 邻近他人歧义或持续高质量负证据 | 当前绑定 ID | 第一批默认停车保护；不更新模板 |
| `lost` | 超过新鲜度+宽限、同 ID 轨迹消失或位置突跳 | 空 | 停止平移；主动搜索/被动找回 |
| `ended` | 30 s 找回截止或任务主动终止 | 空 | 结束并释放任务 |

硬绑定判据：

1. 当前批次 ID 等于绑定 ID。
2. 标签是 `person`，距离和方位均有限且合法。
3. 源时间戳在现有 0.30 s 新鲜度内。
4. 同一 ID 的新位置不得相对平滑预测突跳；突跳立即丢失，没有宽限。
5. 绑定 ID 消失后才允许 ReID 候选 3 帧确认切换到新 ID。

**推测**：默认位置突跳门限沿用现有增长半径 `0.45 + 0.25 * age` m，上限 1.5 m，作为 **待校准** 值并记录。这样做让第一批不发明另一套位置硬门槛；若新车端日志显示 BoT-SORT 单帧抖动仍大，再单独校准。

### 3.2 ReID 登记与监督

ReID 状态：

| 状态 | 含义 | 对几何绑定的影响 |
|---|---|---|
| `enrolling` | 后台持续收集所选 ID 的合格模板，未完成两帧登记 | 无；绑定和掩码照常 |
| `tracking` | 登记完成，持续监督 | 无；正常跟随 |
| `suspect_ambiguous` | 目标附近持续存在其他人物 | 停止平移、冻结模板、保留目标几何 |
| `suspect_negative` | 10 帧高质量窗口中负证据达到阈值 | 停止平移、冻结模板、保留目标几何 |
| `searching` | 几何轨迹断开，正在找回 | 不提供正常运动目标；0–8 s 主动搜索 |
| `passive_reacquire` | 8–30 s 继续用现有候选流和外观阈值找目标 | 原地/被动，不再主动扫描 |
| `unverified` | 登记超时但仍几何连续 | 继续几何跟随；登记仍可迟到完成，完成前禁用自动找回 |
| `ended` | 丢失 30 s 或任务释放 | 结束任务 |

登记规则不变：必须两帧、同 selected ID、第二帧不超过 0.6 s、位置通过；**代码确认**这是当前行为，也是本轮禁止修改项。

新增宽限和超时只包在后台监督外围：

- `enrollment_timeout_s` 默认 **10.0 s（待校准）**。到时尚未完成、但几何仍连续：进入 `unverified`，正常跟随且禁用自动找回。
- 登记完成前真正几何丢失：立即结束任务并报告 `target_lost_before_enrollment`。
- `enrollment_speed_cap_enabled` 默认 **false（待校准）**；可有 `enrollment_speed_cap_mps=0.30（待校准）`。0.3 m/s 是建议初值，不是用户指定值。为避免第一次提交就改控制行为，默认不启用；邻近歧义保护仍始终启用。

### 3.3 缺测宽限

- **代码确认**：当前相对观测源新鲜度为 0.30 s，`target` 的 `VisualTrack` coast timeout 为 0.8 s。
- **推测**：新增 `binding_missing_grace_s=0.20 s（待校准）`，从 0.30 s 新鲜度结束之后才开始计算，因此总绑定保留窗约 0.50 s。
- 15 Hz 检测周期约 66.7 ms；0.50 s 可跨约 7–8 个名义检测周期。一次漏检或一次队列抖动不应停平移。
- 仍可能出现走走停停：连续检测缺口超过约 0.5 s、深度帧/轮速/求解结果自身超时，或目标行持续缺失但检测批次仍存在。此时绑定进入 `lost`，按丢失策略停车并为搜索提供转向；不会为了保持前进而绕过碰撞检查。
- 位置突跳没有宽限，立即断开并触发找回。

## 4. 可疑状态与退出条件

### 4.1 两类可疑

1. `suspect_ambiguous`：目标与至少一个其他路人的中心距离小于 `neighbor_ambiguity_radius_m=1.50 m（待校准）`。第一批只用现有 ID/位置/方位计算；框重叠留到第二批。
2. `suspect_negative`：最近 `supervision_window_size=10（待校准）` 个高质量外观帧中，相似度低于 `0.80` 的负证据达到 `suspect_negative_frames=6（待校准）`。低质量、截断、遮挡、无特征批次记为“无证据”，不进入分子或分母，不更新模板，也不累计失败。

**代码确认**：当前次佳差 `0.08` 是两个同时满足相似度 `>=0.80` 和位置门限的候选，对当前模板集合的最大相似度之差。若只有一个合格候选，就不存在次佳差。**代码确认**：框重叠的现有内部定义是交面积除以两框面积中较小者，大于 0.25 即判 `crop_overlap`，不是 IoU；框是图像像素轴对齐框。该框交叠判断当前在检测器内部产生外观特征前使用，并没有随 `relative_objects` 传到跟随端。

### 4.2 退出和超时

- `suspect_ambiguous`：其他近邻离开并连续 `neighbor_clear_hold_s=0.50 s（待校准）` 无歧义，再加 1 个新的高质量帧：相似度 `>=0.80`、位置通过、次佳差规则通过。通过后恢复 `tracking`。
- `suspect_negative`：最近 10 帧中重新满足正证据恢复条件，或仅当几何连续、周围无他人时通过视角扩充增加合格模板并重新验证。具体默认恢复条件与负证据阈值对称，即窗口内正向/合格比例回到不超过负证据阈值；参数待校准。否则继续可疑。
- 两类可疑都由 `suspect_timeout_s=12.0 s（待校准）`兜底。登记已完成时超时转 `lost`，随后按 30 s 总丢失窗口结束任务；登记未完成时直接结束任务并报告 `suspect_timeout_before_enrollment`。
- 第一批可疑期间默认停车，不新增慢速档；这个选择避免在身份歧义下继续靠近。

## 5. 模板视角扩充

**推测**：正面登记、随后车从背后跟随是现实且高风险场景。背面样本对正面模板可能低于 `0.80` 或 `0.90`，若只允许 `>=0.90` 更新，模型永远无法学习背面，负证据会把状态推入可疑。

实现策略：

- 保留强匹配模板更新门槛 `>=0.90`，不得修改。
- 几何连续、周围在 `view_expansion_neighbor_radius_m=1.50 m（待校准）` 内无其他人时，允许相似度 `>=view_expansion_similarity=0.75（待校准）` 的合格观测扩充模板。
- 扩充最短间隔 `view_expansion_min_interval_s=1.0 s（待校准）`，总模板仍最多 8 个。
- 前 `view_expansion_initial_slots=2（待校准）` 个初始登记模板受保护，不被普通扩充淘汰；剩余 `view_expansion_max_slots=6（待校准）` 个槽位用于视角扩充和强匹配。**推测**：保留 2 个初始正/近正模板适合目前两帧登记；若数据表明背面更强混淆，可把保护数改为 1，但必须回放验证。
- 周围有他人时冻结所有普通模板更新；强匹配阈值仍为 0.90，但冻结期间即使达到门槛也不写模板。歧义清除并重新验证后才恢复。
- 每次写入日志记录 `strong_match`、`view_expansion`、`frozen_neighbor_ambiguity`、`frozen_suspect`、`gallery_full_protected_initial` 等原因。

污染风险及缓解：0.75 比强匹配低，可能把相似衣着的人写进模板。缓解包括几何连续、1.5 m 近邻冻结、低频更新、最多 6 个扩充槽、前 2 个初始模板保护、可疑时完全不更新。**推测**：这些只能降低风险，不能证明不会漂移；需要用真实正背面序列和两人交叉序列校准 0.75、1.5 m 与更新频率。

## 6. 找回时间轴

- 目标当前几何丢失超过 0.50 s 后进入 `lost`。
- 0–8 s：**代码确认**现有 `BlockedRecovery.update_search()` 已从最后真实观测出发，先转向预测方位，再进行有界扇形搜索，`search_s=8`；平移保持零。新策略继续使用该逻辑。
- 8–30 s：停止主动扫描，保持原地或最后安全朝向；继续使用现有候选流、空间门限、`0.80 / 0.08 / 3 帧` 找回。当前 `candidate_ids()` 在 `max_lost` 前可用；新监督器把该时间上限接到 30 s，但不改找回阈值。
- 30 s：调用既有任务终止路径结束任务并释放 lease，状态和日志必须记录 `lost_task_release`。未登记完成前真正丢失直接结束，不等待 30 s。
- 目标在 30 s 内通过 3 帧确认找回后，几何绑定切换到新确认 ID，重启正常监督。

全人物 2 s 缓冲和新消息协议延后，因此第一批找回依赖当前目标/空间候选特征流；这是本批的已知能力边界。

## 7. 目标掩码与地图

- **代码确认**：当前掩码只有在 `resolved_id` 非空时应用；身份进入 `searching` 或 `expired` 后 `resolved_id` 为空，目标自身像素可重新进入匿名占据地图。
- 第一批把掩码有效性绑定到几何绑定，而不是 ReID 的 `tracking` 文本状态：`bound_untracked`、`bound_tracking`、`bound_coasting` 和 `suspect` 均允许应用当前帧目标掩码；真正的 `lost`/`ended` 不应用。
- 掩码仍只处理当前 RGB-D 帧；它不证明历史目标格安全，也不删除历史格。目标归属格豁免延后。
- **推测**：可疑时继续应用目标掩码，与“ReID 不得切断目标掩码”的总原则一致；目标在该阶段仍由几何 ID 定义。若后续主张可疑目标应作为普通路人避障，需要另做“人物通道/静态通道分离”，不能用掩码失效绕过。
- 全人物人物通道、占据来源记录和历史重分类延后。原因和重启条件见 1.1。

## 8. 前方检查截断与倒车

### 8.1 前方检查截断

第一批最早提交就把无绕行路线的直线目标参考截断为：

```text
L_check = min(front_check_max_m, max(0, L_route - front_check_target_offset_m))
```

本轮按用户要求取 `front_check_max_m=1.4 m`、`front_check_target_offset_m=0.87 m`；其他障碍/路人的预测检查、0.316 m 门限和 MPC 扫掠条件不改。**代码确认**：现有 `_path_samples()` 最多检查 1.4 m，并可能直达目标中心；本变更是减少“目标中心附近自身点”被当近障碍的机会。

合成回归场景：

1. 用户表面约 1.0 m，人体中心按 0.28 m 偏移约 1.28 m；人体表面点发任务前已在占据图。直线参考长度约 1.28 m，截断后只检查约 0.41 m，目标点位于检查范围外，不触发 `front_blocked`。
2. 若“1 m”被理解为中心，则直线参考约 1.0 m，截断后只检查约 0.13 m；按 0.28 m 人体模型，表面约 0.72 m，同样在检查范围外，不触发 `front_blocked`。
3. 测试断言采样范围最大值分别约 0.40 m 和 0.10–0.13 m，并确认图上人体点不会使该目标参考触发前方阻挡。其他位于截断范围内的真实障碍仍必须触发。

### 8.2 倒车开关关系

- `retreat_disabled` 默认 **false（待校准）**，是全局禁止倒车开关；在旧分支和新分支都生效。false 保持兼容配置的旧倒车路径。
- `reverse_policy_v2` 默认 **false（待校准）**，在兼容预设中关闭。第一批新预设启用它，但该策略默认“不自动倒车”；因此新预设即使 `retreat_disabled=false` 也不会因持续前方阻挡自动倒车。
- 只有当未来显式打开新策略的自动倒车资格，并且 `retreat_disabled=false`、目标已真实丢失、`rear_clear` 通过时才允许。`rear_clear` 数值和阈值完全不变。
- 全关兼容预设必须精确保持 `retreat_disabled=false + reverse_policy_v2=false` 的旧路径与 300 帧差分一致。

## 15. 风险清单

- **推测**：两人交叉但 BoT-SORT ID 未变时，几何绑定会继续选择原 ID；ReID 只有持续高质量负证据/近邻歧义才转可疑。保护是停车优先、不更新模板、超时结束，代价是可能停住。
- **推测**：相似衣着会污染视角扩充模板；保护是 0.75 仅用于无近邻、几何连续、低频、6 个扩充槽和 2 个初始模板保护。
- **推测**：目标框比人物实际范围小或大时，深度掩码可能残留或删多；第一批沿用现有分割掩码和 0.35 m 深度带，不在本轮调阈值。
- **推测**：0.5 m 缺测保留在目标突然真正消失时可能让车短暂按 Kalman 前进；默认值待校准，所有全局碰撞检查仍运行。若实车首次测试显示前向惯性风险，应关闭新预设并重新评估，而不是放宽碰撞检查。
- **推测**：旧分支的 `rear_clear` 通过不等于真实后方安全；新预设默认不倒车，正是为保持这一点。
