# 2026-10-13 OpenVINS 原工作区接入

本轮使用 D455 内置 IMU。`--openvins` 默认选择 `r680_d455_20261013`，输入 `/r680/d455/imu`，frame 为 `d455_imu_optical_frame`。不把外置底盘 IMU 同时融合到 OpenVINS。RTAB-Map 不重复融合该 IMU，OpenVINS 分支不启动既有 cuVSLAM、平面 EKF、degraded odometry 或自动重启 watchdog。

## 入口

实际 shell 实现在 `/home/orin/ros2_ws/r680_nav.sh`、`r680_mapping.sh`、`r680_teleop.sh`。包内同名脚本及 installed 入口是薄转发，默认指向 `$HOME/ros2_ws`，可用 `WLA_NAV_WORKSPACE` 指定其他完整工作区。只分发 installed 包而没有根脚本不再构成完整启动部署。

```bash
cd ~/ros2_ws
./r680_nav.sh --openvins --openvins-imu d455 --map map-2026-10-08-1 --test-scan-only
./r680_mapping.sh --openvins --openvins-imu d455
./r680_teleop.sh --help
```

`--openvins-config /absolute/directory` 选择另一套完整配置；不能只换 IMU topic 而沿用另一颗 IMU 的外参和时间偏移。保留 `--openvins-imu wheel` 作为显式诊断选项，本轮现场验证不使用它。

`--map`、`--enable-motion`、`--test-scan-only` 原参数保留。当前 OpenVINS `--enable-motion` 在任何服务暂停或传感器启动前拒绝：标定和运行能力尚未验收。该拒绝不影响其他前端原有路径。每次 nav/mapping 保存实际配置快照，检查配置哈希及 topic/frame。导航预览和失败清理均保留独立 `r680-manual-base.service`，供操作者手柄干预。

提交 `0e19c5651d8850964d0c5d07fe2a8aa0aae68eff`（`feat(nav): integrate shared perception and unified launch ownership`）将 nav/mapping 根入口改为转发 installed 实现，以集中共享感知、互斥锁及服务生命周期。teleop 根入口的符号链接更早已存在，该提交还恢复了它的可执行属性，并非三个脚本都由该提交首次迁入包内。本轮将实现恢复根目录，同时保留上述资源所有权逻辑。

## 初始化与安全路径

当前 `try_zupt=false`、`init_dyn_use=false`，每次前端进程重启都重新初始化：先静置，再提供合适的运动激励。当前版本没有承诺全静态启动，也不会在未初始化时伪造 odom。

显式 `--auto-vio-init` 支持 OpenVINS 初始化运动预览，默认关闭。它读取选中配置的 IMU，要求图像、IMU、轮速、深度、安全点云和真实新鲜 GROUNDED。UNKNOWN 不会因轮速为零转换成接地。前端 instance/generation 变化、非零手柄命令或接地丢失会中止并锁定。

普通 Nav2 激活需要 odom TF；初始化前没有该 TF。因此预览使用独立的 `vio_init_velocity_smoother`、`vio_init_collision_monitor` 和 `lifecycle_manager_vio_init`。后者延迟 3 s 启动。碰撞检查沿用原安全点云和几何，初始化预览分支设置 `base_shift_correction=false`；普通导航的碰撞监视器不变。该设置尚未实车验收，不能据此开启硬件输出。

预览沿用受限预算：静置 3 s，约 0.06 m/s、0.20 rad/s，目标 0.16 m，最大累计路程/半径 0.25 m、偏航 0.35 rad，激励 8 s，初始化 20 s，不倒车。这些是候选运行预算，不是测得的制动能力。

接口就绪检查不再用 commissioning 永远 false 的运动许可阻塞定位预览。最终 `command_guard` 独立要求新鲜 `/openvins/motion_ready`，且 OpenVINS launch 仍禁止硬件输出。预览可就绪不等于允许底盘运动。

OpenVINS 普通导航还使用 `openvins_nav_startup.py` 分阶段激活：Nav2 lifecycle manager 的 autostart 关闭，先等初始化后的有效状态、新鲜 mapping odom 和 map→base TF，再仅请求一次 STARTUP。初始化等待上限 300 s，激活响应上限 120 s，根入口总就绪等待 450 s。超时或激活失败不会自动重试；其他前端维持原 autostart 和 120 s 入口等待。此改动消除“尚未产生 odom，Nav2 却已启动其 TF 超时”的顺序错误，没有放宽运行期里程计新鲜度或输出门。

### 现场结果

证据根目录：`/home/orin/nav_run/openvins_integration_20261013/`。

- `live_final`：启动异常样本被丢弃后，D455 数据恢复正常，没有锁存 IMU 故障。尚无里程计时 Nav2 先超时退出；因此增加上述分阶段激活。该轮用户动作反馈晚于采集窗口，不能当成初始化验收。
- `live_staged`：捕获手柄动作并成功静态初始化；用户随后说明相机可能一直朝向白墙。135.6 s bag 中，初始化后未达到有效视觉跟踪判据，单次接受特征最多 1 个，纯惯性输出严重发散。离线 D455 回放复现失效；没有注入真值或放宽噪声/门限。白墙是用户报告的场景线索，不能凭这轮直接排除代码或标定问题。
- `live_textured`：用户更换视野后重新手柄初始化，实际参数查询确认 IMU 为 `/r680/d455/imu`、frame 为 `d455_imu_optical_frame`，底盘 IMU 没有订阅者，odom 唯一发布者为 `/openvins/openvins_frontend`。约 340 s 观察中收到 34,947 条原始 odom、6,578 条 mapping odom。RTAB-Map 接收门控里程计，map→base TF 连通，controller/planner/bt_navigator/velocity_smoother/collision_monitor/map_server 均曾达到 active，根入口通过预览就绪检查。
- 有纹理场景的 150 s bag 中单次接受特征最多 26 个；初始化后 1,410 条状态里有 188 条 VIO_TRACKING、84 条 RECOVERING、1,138 条 INERTIAL_ONLY。采样比例不是定位误差指标，但说明健康状态仍频繁降级，须核对稀疏 MSCKF 更新与当前“单次特征数 + 新鲜度”判据的关系，不能直接降低门限通过。
- 用户确认始终在同一平地行驶、没有抱起或明显升降，随后补充行驶颠簸严重。因此运动中的 z 起伏不能全部认定为误差；但若前后停稳时底盘实际高度相同，估计 base 高度从约 -0.495 m 变为 -1.61 m 所留下的约 1.12 m 偏差仍未通过精度验收。初始负 z 主要来自 IMU 原点到 base 的安装偏移，并非相对地面的绝对高度。停稳后两次相隔约 54 s 的读数相差约 2.6 cm，仅支持该静置片段的相对稳定性。
- `live_textured/height_bumps_analysis.json` 对全部 14,490 条 odom 和 29,823 条 IMU 做只读分析：比力模长最高 46.19 m/s²（约 4.71 g，包含重力），角速度模长最高 5.69 rad/s。强动态值得排查，但这些峰值本身不能证明饱和、器件故障或唯一误差来源。根据已发布姿态和当前安装外参计算，IMU→base 换算项的 z 峰峰值仅约 0.0112 m，首末 5 s 中位数变化约 0.00029 m；对应 base z 中位数变化约 -1.123 m。因此当前换算项不能解释米级差值。上述姿态不是独立真值，首末窗口也不是外部确认的静止标签。
- 当前 z 来自同一个 VIO 状态：D455 IMU 推进，双目特征校正，再换算到 base。INERTIAL_ONLY 是包装层按单次接受特征数和新鲜度定义的健康状态，不等于该时段绝对没有任何视觉更新。现有 bag 没有记录每次视觉更新前后的状态，不能精确拆分 IMU 传播和视觉校正各自造成的高度变化。需要进一步离线回放记录这两部分，结合时序、重力/偏置、外参和视觉残差定位。
- D455 内置 IMU 与双目光学坐标系仍通过相机–IMU 外参联系；输出到 base 使用相机/IMU 到底盘的固定安装变换。base 是底盘参考坐标系，不是外置底盘 IMU 的坐标系；本分支没有融合外置 IMU，也不需要先转换到该 IMU。
- 最后的短时 RTAB-Map 探针收到同时间戳的 info 与 localization_pose，但该 info 的 loop/proximity ID 都是 0；有地图 TF 和位姿输出不能证明已成功匹配到历史地图。没有下发自主导航目标。
- 所有现场轮次保留候选标定未验收状态（`kind:commissioning`、`calibration_validated:false`），硬件导航输出关闭。`contact_state` 无真实发布者，运动许可始终未开放。底盘非零命令来自操作者手柄；清理后 `r680-manual-base.service` 仍 active，本轮导航、相机、回放和录制进程均已退出。

结论：完成原系统接口和预览链路验证，未完成导航精度及部署验收。下一步优先用所录数据检查运动段高度误差、视觉残差/特征筛选、相机 IMU 时间和外参一致性；再独立验证真实地图匹配、接地接口、1/3/5/10 s 遮挡和搬运。当前不能宣称长时仅 IMU 的 XYZ 稳定精度，也不应开放 `--enable-motion`。
