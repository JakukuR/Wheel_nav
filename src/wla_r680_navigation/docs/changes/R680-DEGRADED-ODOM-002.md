# R680-DEGRADED-ODOM-002：迟到视觉帧不再打断短时接管

运行 `nav-20261009-142846-76169` 在 14:30:54 进入降级后约 44 ms，
一帧约 192 ms 的视觉输出超过 150 ms 新鲜度阈值。原 `onRaw()` 将
迟到帧与非法位姿合并处理，直接硬锁并触发看门狗重启，绕过了既定接管窗口。

现将有效但迟到的帧丢弃，不更新可信视觉位姿/新鲜度，不计入恢复帧数，也不
重置接管预算。新鲜度同时检查接收时间与采集时间，避免刚收到的旧帧延长
可信期限。位姿格式/数值/协方差非法、未来时间戳超过 20 ms 仍硬锁。

增加限频日志与 `/r680_nav/continuous_odom_status` 的 `late_visual_frames`
计数。轮速与 IMU 新鲜度、地图锚点、2 s/0.30 m/0.80 rad 接管预算、
不确定性门限、三个一致视觉帧恢复要求、碰撞监测与最终输出限速均保持。

回归覆盖 192 ms 延迟后接回、持续延迟到预算停车、非法位姿硬锁与未来
时间戳硬锁，使用隔离 ROS_DOMAIN_ID=174、假传感器与预览门控，无实车指令。

验证结果：原安装版本的迟到帧回归可复现硬锁；修复后的 20 个隔离 ROS
场景全部通过，3 个降级/恢复规则 CTest 全部通过，Release 编译安装成功。
