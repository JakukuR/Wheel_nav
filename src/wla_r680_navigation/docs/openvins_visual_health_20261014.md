# OpenVINS 已初始化但导航零输出：2026-10-14 修正

现场运行 `nav-20261014-110609-149056` 已交接 AUTO/NAV，任务许可、自动授权和硬件输出开关均开放，急停未锁存。RViz 目标已被接收，随后因无法取得进展而失败。

只读采样发现 `tracking_healthy=false`、`localization_ready=false`，图像、IMU 和原始 odom 新鲜，状态与不确定度均合格。随后 12 秒采样的 241 条状态中，接受特征数为 0/1/2/4，始终为 INERTIAL_ONLY。状态采样可能重复同一次相机结果，不能把状态条数当作 EKF 更新次数。

原包装层要求每次至少接受 8 个 MSCKF 特征才更新视觉时间戳。这不是 OpenVINS 的 EKF 更新成立条件；现有补丁在实际 `StateHelper::EKFUpdate` 后增加更新序号。1～7 个通过估计器筛选并执行修正的特征被包装层错误忽略，造成“数分钟没有视觉更新”的误报。

修正后依据实际更新序号前进、正接受特征数和递增相机时间戳记录视觉修正。移除包装层 `min_accepted_features` 参数；特征数仍作为诊断输出。初始化状态、有效状态、IMU/图像时效、0.5 秒视觉时效、连续 3 次修正恢复和原有协方差限制继续生效。不能把本次修正解释为已完成 10 秒盲导航或标定精度验收。

同次日志还有生命周期启动失败后外层误报成功：旧代码将地图生命周期管理器的 `Managed nodes are active` 当成导航成功，并可能漏掉阻塞查询期间新写入的失败日志。现在 OpenVINS 分支必须等 `openvins_nav_startup` 收到 STARTUP 成功应答后才查询生命周期；其他分支匹配导航管理器。就绪返回前再次读取失败日志。`collision_monitor/get_state ... async_send_request failed` 的底层原因未由本次证据确定；此修正保证其不再被误报为启动成功。

对应回归：真实 OpenVINS 核心的 7 特征合成更新、空约束丢失与恢复；更新序号不变时不重复计数、协方差不合格不进入 TRACKING；静态地图成功不放行、STARTUP 失败与晚到错误不放行。这些测试均不连接底盘，不是实车导航验收。
